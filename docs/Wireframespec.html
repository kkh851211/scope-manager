문서 개요
화면 설계서(Wireframe Spec)의 목적, 기능 명세서와의 차이, 와이어프레임 읽는 법, 표기 규칙, 레이아웃 존 범례를 정의합니다.
📌 이 문서의 목적과 사용 방법

화면 설계서는 Scope Manager의 각 화면이 시각적으로 어떻게 구성되는지를 정의하는 문서다. 레이아웃 영역 배치, 컴포넌트 배치 위치, 화면 간 전환 흐름을 박스 기반 다이어그램으로 표현한다.

누가 사용하는가 — Antigravity(AI IDE)로 실제 UI를 구현하기 전에 레이아웃 구조를 확인할 때, 피그마 작업 전 정보 구조를 빠르게 검토할 때, 팀원(디자이너·개발자)과 화면 구조를 공유할 때 사용한다.

어떻게 읽는가 — 각 화면 카드는 ① 레이아웃 다이어그램 → ② 영역 설명 → ③ 화면 흐름 → ④ 설계 주석 순서로 구성된다. 와이어프레임은 시각적 완성도가 아닌 구조와 흐름을 전달하는 것이 목적이다.

화면 설계서 작성 원칙
"레이아웃 구조 → 화면 흐름 → 핵심 인터랙션 순서로 설계한다.
상태 변화가 있는 화면은 상태별 레이아웃을 별도로 표현한다."
박스 다이어그램은 실제 픽셀 크기가 아닌 비례 관계를 표현한다. 색상은 영역 유형(내비게이션·콘텐츠·액션·폼)을 구분하는 용도로만 사용한다.

⚠️ 와이어프레임 해석 시 주의 사항

색상 의미 구분 — 와이어프레임의 색상은 영역 유형을 구분하기 위한 것이며, 실제 UI 색상과 무관하다. 실제 UI 색상은 기존 디자인 시스템의 "Calm Authority" 다크 네이비 팔레트를 따른다.

크기 비례 — 박스의 크기는 실제 픽셀 크기가 아닌 상대적 비중을 나타낸다. 정확한 크기 값(240px 사이드바, 1024px 최소 너비 등)은 기능 명세서의 레이아웃 섹션을 참조한다.

모바일 미지원 — MVP는 데스크탑 전용(최소 1024px). 모든 와이어프레임은 데스크탑 뷰를 기준으로 작성됐다.
