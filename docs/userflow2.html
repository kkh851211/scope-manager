ScopeManager
User Flow MVP 단계
Flow 1. 회원가입 & 온보딩
신규 사용자의 가입부터 첫 빈 화면 대시보드 진입까지의 흐름입니다.
1
사용자가 서비스 랜딩 페이지에 진입한다
2
"무료로 시작하기" CTA 버튼을 클릭한다
3
가입 방식을 선택한다
  • 3-A. 이메일 + 패스워드 입력 후 가입 버튼 클릭: 입력한 이메일로 인증 메일 발송 → 이메일 인증 링크 클릭 → 인증 완료 → 온보딩 화면으로 이동
  • 3-B. Google 계정으로 계속하기 클릭: Google OAuth 동의 화면 표시 → 계정 선택 및 권한 승인 → 인증 완료 → 온보딩 화면으로 이동
4
시스템이 organization(워크스페이스)을 자동 생성하고 사용자와 연결한다
5
빈 상태(Empty State) 대시보드가 표시된다
  • 화면 중앙에 "첫 프로젝트 만들기" CTA 버튼 표시
  • "30초 만에 첫 판정 받기" 안내 문구 표시
  • 3단계 온보딩 가이드 (프로젝트 등록 → 요청 입력 → 리포트 생성) 표시
6
PostHog에 user_signed_up 이벤트가 기록된다
Flow 2. 로그인
1
사용자가 /login 페이지에 진입한다
2
로그인 방식을 선택한다
  • 2-A. 이메일 + 패스워드 입력 후 로그인
  • 2-B. Google 계정으로 로그인
3
인증 성공 시 홈 대시보드(/)로 리다이렉트한다
미인증 상태에서 보호 경로 직접 접근 시 /login으로 리다이렉트한다.
비밀번호를 잊은 경우
  • "비밀번호 재설정" 링크 클릭
  • 이메일 입력 후 재설정 메일 요청
  • 이메일 수신 → 재설정 링크 클릭
  • 새 비밀번호 입력 후 저장 → 로그인 화면으로 이동
Flow 3. 프로젝트 생성 & 계약 범위 등록
새로운 프로젝트를 만들고 AI 파싱을 통해 계약 범위를 구조화하는 흐름입니다.
1
대시보드에서 "새 프로젝트 만들기" 버튼을 클릭한다
2
프로젝트 정보를 입력한다
  • 프로젝트명 (필수)
  • 클라이언트명 (필수)
  • 계약 시작일 (필수)
  • 계약 금액 (선택)
3
계약서 보유 여부를 확인한다
  • 3-A. 계약서 있음: 계약 범위 텍스트 입력 단계로 이동
  • 3-B. 계약서 없음 (구두 계약 등): "계약 범위 직접 작성 가이드" 팝업 표시 → 가이드 양식에 따라 범위 항목 직접 작성 → 작성 완료 후 동일 흐름으로 진행
4
계약 범위 텍스트를 textarea에 입력한다 (최대 5,000자)
5
"범위 등록 및 파싱 시작" 버튼을 클릭한다
6
시스템이 Claude API를 1회 호출하여 계약 범위를 구조화 항목으로 파싱한다
로딩 인디케이터가 표시됩니다.
7
파싱된 항목 목록이 미리보기로 표시된다
8
PM이 파싱 결과를 검토한다
  • 8-A. 항목 수정이 필요한 경우: 직접 편집 후 저장
  • 8-B. 항목이 맞으면: "확정" 버튼 클릭
9
scope_definitions 테이블에 JSON으로 저장된다
프로젝트 상태가 "진행 중"으로 설정되고 프로젝트 상세 페이지로 이동합니다.
10
PostHog에 first_project_created 이벤트가 기록된다
⚠️ Free 플랜 프로젝트 제한

Free 플랜 사용자가 프로젝트 3개 초과 생성 시도 시:
1. 업그레이드 유도 모달 표시
2. "Starter로 업그레이드" 또는 "닫기" 선택
3. 닫기 선택 시 해당 월 동안 모달 재표시 없음

Flow 4. 클라이언트 요청 입력 & AI 범위 판정
클라이언트 요청을 분석하여 판정 결과를 제공하는 핵심 흐름과 에러 핸들링입니다.
1
프로젝트 상세 페이지에서 "새 요청 판정하기" 버튼을 클릭한다
2
Free 플랜 월 판정 잔여 횟수를 확인한다
  • 2-A. 잔여 횟수 있음: 입력 단계로 이동
  • 2-B. 잔여 횟수 없음 (월 10회 소진): 업그레이드 유도 모달 표시 ("이번 달 AI 판정 10회를 모두 사용했습니다") → "Starter 업그레이드" 또는 "닫기" (닫기 시 판정 불가 유지)
3
클라이언트 요청 내용을 textarea에 입력한다 (최대 2,000자)
4
"판정 시작" 버튼을 클릭한다
5
시스템이 Fast Path 체크를 실행한다
5-A. Fast Path 적중 — Claude API 호출 없음 (1초 이내 결과 표시)
  • 완전 일치: 코사인 유사도 ≥ 0.92 → "범위 내" 즉시 반환
  • 명백한 신규: 최대 유사도 ≤ 0.35 → "범위 초과" 즉시 반환
  • 중복 요청: 동일 SHA-256 해시 캐시 발견 → 캐시 결과 반환
  • PM 오버라이드 패턴: 유사도 ≥ 0.88 → 오버라이드 기록 우선 적용
5-B. Claude API 호출 — 유사도 0.35 초과 0.92 미만
  • Claude API 호출 (temperature 0.2 고정)
  • 스트리밍 응답으로 결과 표시 (목표 15초 이내)
  • 판정 결과 및 근거 문장 표시
6
판정 결과 3단계 중 하나가 표시된다
  • 범위 내 → Flow 4-A로 이동
  • 판단 필요 → Flow 4-B로 이동
  • 범위 초과 → Flow 4-C로 이동
판정 근거 문장이 함께 표시된다 (계약서 어느 항목과 비교했는지 명시)
scope_requests 테이블에 판정 결과가 자동 저장된다.
7
PostHog에 이벤트가 기록된다
`first_scope_judgment` (첫 판정 시) 또는 `scope_judgment_completed` 기록.
Flow 4-A. 범위 내
  • "범위 내" 결과와 근거 문장 표시
  • PM이 결과를 확인한다.
  • 동의: 판정 완료. 히스토리에 기록. (플로우 종료)
  • 동의 안함: "재판정 요청" 클릭 → Claude API 재호출.
Flow 4-B. 판단 필요
  • "판단 필요" 결과와 근거 문장 표시
  • PM이 수동으로 최종 판정을 선택한다. (오버라이드 기록 저장)
  • "범위 내" 선택: 플로우 종료
  • "범위 초과" 선택: Flow 4-C로 연결
Flow 4-C. 범위 초과
  • "범위 초과" 결과와 근거 문장 표시
  • PM이 결과를 확인한다.
  • 동의: "리포트 생성하기" 버튼 활성화 → Flow 5로 이동
  • 동의 안함: "재판정 요청" 클릭 → API 재호출.
Flow 4-D. 에러 처리
  • Claude API 타임아웃 (30초 초과): 자동으로 1회 재시도. 재시도 실패 시 "일시적 오류" 메시지 + 수동 판정 모드 제공.
  • Claude API 연속 2회 실패: 수동 판정 모드 자동 전환. "AI 판정 일시 중단" 배너 표시. PM이 수동으로 직접 결과 선택.
  • Supabase 연결 오류: 입력 내용을 로컬 세션 스토리지에 임시 저장. 연결 복구 후 자동 동기화.
  • 판정 중 브라우저 새로고침: `status` 컬럼(pending/completed/failed) 확인 후 pending이면 재시도 안내, 완료면 결과 복원.
Flow 5-7. 리포트 자동 생성 및 발송
범위 초과 시 리포트를 생성하고 클라이언트에게 전달하는 흐름입니다.
Flow 5. 리포트 자동 생성 (AHA 모멘트)
1
"범위 초과" 판정 결과 화면에서 "리포트 생성하기" 버튼을 클릭한다
2
Free 플랜 월 리포트 잔여 건수를 확인한다
  • 2-A. 잔여 건수 있음: 생성 단계로 이동
  • 2-B. 잔여 건수 없음 (월 3건 소진): 업그레이드 모달 표시 ("이번 달 리포트 3건 모두 사용") → "Starter 업그레이드" 또는 "닫기"
3
시스템이 Claude API를 1회 호출하여 리포트 초안을 생성한다
  • 로딩 인디케이터 표시 (목표 10초 이내)
  • 프롬프트 내 금지 표현 목록 적용 ("죄송합니다", "유감입니다" 등 감정 언어 금지)
4
리포트 초안이 표시된다
구성: 프로젝트명 / 요청 일시 / 요약 / 판정 결과 / 계약 근거 / 추가 비용 안내 문구 (중립적 시스템 어조)
5
PM이 리포트 내용을 검토한다
  • 5-A. 수정 필요 시: 편집 모드 진입 → 내용 수정 → 저장
  • 5-B. 수정 불필요 시: "리포트 확정" 버튼 클릭
6
확정된 리포트가 DB에 저장되고, 미리보기가 표시된다
PDF 다운로드 버튼이 활성화(Flow 6). Starter 이상은 이메일 발송 버튼 활성화(Flow 7).
7
PostHog에 report_generated 이벤트가 기록된다
⭐ AHA 모멘트 추적 완료
Flow 6. PDF 다운로드
  • 리포트 확정 화면에서 "PDF 다운로드" 버튼을 클릭한다
  • 브라우저 `window.print()` 실행 → PDF 저장 다이얼로그 표시
  • 사용자가 저장 위치 지정 후 다운로드 완료
  • PostHog에 `pdf_downloaded` 이벤트가 기록된다
Flow 7. 이메일 발송 (Starter 이상)
  • 확정 화면에서 "이메일 발송" 버튼 클릭 (Starter 이상)
  • 클라이언트 이메일 주소 입력
  • 발송 전 리포트 미리보기 확인 (실수 방지)
  • 발송 진행("발송하기") 또는 취소
  • 발송 완료 후 상태 "발송 완료" 변경 및 이력 DB 기록
Flow 8-10. 대시보드 & 플랜 업그레이드
프로젝트 현황을 파악하고 유료 플랜으로 업그레이드하는 흐름입니다.
Flow 8. 히스토리 타임라인 조회
  • 프로젝트 상세 페이지에서 "요청 히스토리" 탭을 클릭한다
  • 해당 프로젝트의 전체 판정 이력이 시간 순으로 표시된다 (일시 / 요약 / 결과 / 발송 여부 / 청구 상태)
  • 판정 결과별 초록 노랑 빨강 색상 구분 적용
  • 결과별 필터(전체/범위 내/초과/판단 필요)를 선택하여 정렬한다
  • 개별 요청 항목을 클릭하면 상세 판정 결과 및 리포트 확인 화면이 표시된다
Flow 9. 홈 대시보드 확인
1
로그인 직후 홈 대시보드(/)로 랜딩한다
2
프로젝트가 없는 경우
  • 빈 상태(Empty State) UI 표시
  • "첫 프로젝트 등록하기" CTA 버튼 노출 → Flow 3으로 이동
3
프로젝트가 있는 경우
  • 핵심 수치 4개 카드 표시: 진행 중 프로젝트 수, 이번 달 추가 요청 건수, 청구 성공 건수, 누적 방어 금액
  • 손익 위험 프로젝트 목록: 적자 가능성 높은 순으로 정렬되어 표시
  • 최근 판정 이력: 최신 5건이 요약 표시됨
  • 목록 클릭 시 해당 상세 페이지로 이동
Flow 10. 플랜 업그레이드
  • 기능 제한 모달이 표시되거나 설정에서 플랜 변경을 클릭한다
  • Free / Starter / Pro 플랜 비교 화면이 표시된다
  • 원하는 플랜의 "업그레이드" 버튼을 클릭한다
  • 결제 정보 입력 화면으로 이동한다
  • 결제 완료 후 해당 플랜 기능이 즉시 활성화된다
  • PostHog에 `upgrade_modal_shown` → `plan_upgraded` 이벤트가 기록된다
