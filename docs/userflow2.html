ScopeManager
User Flow v1.3
Flow 1. 회원가입 & 온보딩
신규 사용자의 가입부터 첫 빈 화면 대시보드 진입까지의 흐름입니다.
1
사용자가 서비스 랜딩 페이지에 진입한다
2
"무료로 시작하기" CTA 버튼을 클릭한다
3
가입 방식을 선택한다
  • 3-A. 이메일 + 패스워드: 인증 메일 발송 → 링크 클릭 → 인증 완료 → 온보딩 이동
  • 3-B. Google 계정: OAuth 동의 화면 → 계정 선택/권한 승인 → 온보딩 이동
4
시스템이 organization(워크스페이스)을 자동 생성하고 사용자와 연결한다
5
빈 상태(Empty State) 대시보드가 표시된다
  • 화면 중앙에 "첫 프로젝트 만들기" CTA 버튼 표시
  • "30초 만에 첫 판정 받기" 안내 문구 표시
  • 3단계 온보딩 가이드 표시: 계약 등록 → 요청 판정 → 리포트 생성
6
PostHog에 user_signed_up 이벤트가 기록된다
Flow 2. 로그인
1
사용자가 /login 페이지에 진입한다
2
로그인 방식을 선택한다
  • 2-A. 이메일 + 패스워드 입력 후 로그인
  • 2-B. Google 계정으로 로그인
3
인증 성공 시 홈 대시보드(/)로 리다이렉트한다
미인증 상태에서 보호 경로 직접 접근 시 /login으로 리다이렉트한다.
비밀번호를 잊은 경우
  • "비밀번호 재설정" 링크 클릭
  • 이메일 입력 후 재설정 메일 요청
  • 이메일 수신 → 재설정 링크 클릭
  • 새 비밀번호 입력 후 저장 → 로그인 화면으로 이동
Flow 3. 프로젝트 생성 & 계약 범위 등록
새로운 프로젝트를 만들고 AI 파싱을 통해 계약 범위를 구조화하는 흐름입니다.
1
대시보드에서 "새 프로젝트 만들기" 버튼을 클릭한다
2
프로젝트 정보를 입력한다
  • 프로젝트명 (필수) / 클라이언트명 (필수)
  • 클라이언트 이메일 (선택 — F-06 이메일 발송 시 자동 불러오기 사용)
  • 계약 시작일 (필수) / 계약 종료일 (선택)
  • 계약 금액 (선택) / 금액 유형 (프로젝트 고정 / 월 유지보수)
3
계약서 보유 여부를 확인한다
  • 3-A. 계약서 있음: 계약 범위 텍스트 입력 단계로 이동
  • 3-B. 계약서 없음 (구두 계약 등): "계약 범위 직접 작성 가이드" 팝업 표시 → 가이드 양식에 따라 범위 항목 직접 작성 → 동일 흐름 진행
4
계약 범위 텍스트를 textarea에 입력한다 (최대 5,000자)
입력 중 이탈 시 임시저장 처리. 다음 접속 시 대시보드에 "미완료 프로젝트 이어하기" 배너 표시.
5
"범위 등록 및 파싱 시작" 버튼을 클릭한다
6
시스템이 Claude API를 1회 호출하여 계약 범위를 구조화 항목으로 파싱한다
  • 로딩 인디케이터가 표시된다
  • 파싱 실패 또는 결과 빈약 시: "범위 항목을 자동으로 구성하지 못했습니다. 직접 입력하시겠습니까?" 안내 → 수동 입력 모드 전환
7
파싱된 항목 목록이 미리보기로 표시된다
8
PM이 파싱 결과를 검토한다
  • 8-A. 항목 수정이 필요한 경우: 직접 편집 후 저장
  • 8-B. 항목이 맞으면: "확정" 버튼 클릭
  • PM이 수정한 parsed_items가 이후 판정의 기준으로 사용된다 (raw_text는 보존용)
9
scope_definitions 테이블에 JSON으로 저장된다 (version = 1)
프로젝트 상태가 "진행 중"으로 설정되고 프로젝트 상세 페이지로 이동합니다.
10
PostHog에 `project_created` 및 `scope_confirmed` 이벤트가 기록된다
계약 범위 수정 시 플로우
  • 기존 `scope_definitions` 버전 보존, `version` 증가
  • 이전 판정 이력은 수정 전 버전 기준으로 유지
  • Fast Path 캐시 전체 자동 무효화
  • 화면에 "범위가 수정되었습니다. 이전 판정 이력은 수정 전 기준으로 유지됩니다." 안내 표시
⚠️ Free 플랜 프로젝트 제한
  • Free 플랜 사용자가 프로젝트 3개 초과 생성 시도 시 업그레이드 유도 모달 표시
  • "Starter로 업그레이드" 또는 "닫기" 선택
  • 닫기 선택 시 해당 월 동안 프로젝트 생성 버튼 disabled 유지
Flow 4. 클라이언트 요청 입력 & AI 범위 판정
클라이언트 요청을 분석하여 4단계 판정 결과를 제공하는 핵심 흐름과 에러 핸들링입니다.
1
프로젝트 상세 페이지에서 "새 요청 판정하기" 버튼을 클릭한다
2
Free 플랜 월 판정 잔여 횟수를 확인한다 (재판정 포함)
  • 2-A. 잔여 횟수 있음: 입력 단계로 이동
  • 2-B. 잔여 횟수 없음 (월 10회 소진): 업그레이드 유도 모달 표시 ("이번 달 AI 판정 10회를 모두 사용했습니다") → "Starter 업그레이드" 또는 "닫기" (닫기 시 판정 불가 유지)
3
클라이언트 요청 내용을 입력한다
  • 텍스트 입력 (최대 2,000자)
  • 이미지 첨부 (P1 — 최대 3장. 이미지만 첨부하고 텍스트 비워도 판정 가능)
4
"판정 시작" 버튼을 클릭한다
결과 저장 전 "이 판정을 기록하지 않음" 처리 가능 (Free 플랜은 취소해도 횟수 차감)
5
시스템이 중복 요청 여부를 먼저 확인한다
동일 SHA-256 해시 감지 시: "동일한 요청이 이전에 판정된 적 있습니다. 새로 판정하시겠습니까?" 모달 표시. (새로 판정 / 이전 결과 사용 선택)
6
시스템이 Fast Path 체크를 실행한다
6-A. Fast Path 적중 — Claude API 호출 없음 (1초 이내 결과 표시)
  • 완전 일치: 코사인 유사도 ≥ 0.92 → 이전 판정 결과 재사용
  • 명백한 신규: 최대 유사도 ≤ 0.35 → "범위 초과" 즉시 반환
  • PM 오버라이드 패턴: 유사도 ≥ 0.88 → 오버라이드 기록 우선 적용
6-B. Claude API 호출 — 유사도 0.35 초과 0.92 미만
  • Claude API 호출 (temperature 0.2 고정). 이미지 첨부 시 vision 기능 활용(P1).
  • 스트리밍 응답 표시: "계약 범위를 분석하고 있습니다…" → "요청과 비교하고 있습니다…" → "결과를 정리하고 있습니다…"
7
판정 결과 4단계 중 하나가 표시된다
  • 범위 내 → Flow 4-A
  • 판단 필요 → Flow 4-B
  • 부분 초과 → Flow 4-C
  • 범위 초과 → Flow 4-D
판정 근거 문장이 함께 표시되며, 초과/부분 초과 시 예상 추가 공수 참고치가 표시됩니다.
scope_requests 테이블에 판정 결과가 자동 저장됩니다.
8
PostHog에 이벤트가 기록된다
`first_scope_judgment` (첫 판정 시) 또는 `scope_judgment_completed` 기록.
Flow 4-A. 범위 내
  • "범위 내" 결과와 근거 문장 표시
  • PM 동의: 판정 완료, 히스토리 기록. 리포트 생성 버튼 활성화.
  • 동의 안함(재판정): API 재호출 (횟수 차감).
Flow 4-B. 판단 필요
  • "판단 필요" 결과 표시
  • PM이 수동으로 최종 판정을 선택 (오버라이드 기록).
  • 선택 결과에 따라 범위 내/초과/부분 초과 플로우로 이동.
Flow 4-C. 부분 초과
  • 범위 내 항목과 초과 항목을 구분하여 표시.
  • PM 동의: "리포트 생성하기" 버튼 활성화 → Flow 5 이동.
  • 동의 안함(재판정): API 재호출.
Flow 4-D. 범위 초과
  • "범위 초과" 결과와 근거 문장 표시
  • PM 동의: "리포트 생성하기" 버튼 활성화 → Flow 5 이동.
  • 동의 안함(재판정): API 재호출.
Flow 4-E. 에러 처리
  • API 타임아웃 (30초): 1회 자동 재시도. 실패 시 수동 판정 모드.
  • 연속 2회 실패: 수동 판정 모드 자동 전환 + 배너 표시.
  • Supabase 연결 오류: 로컬 스토리지 임시 저장 후 자동 동기화.
  • 새로고침: `status` 컬럼 확인 후 pending이면 재시도 안내, completed면 결과 복원.
Flow 5. 리포트 자동 생성 (AHA 모멘트)
판정 결과를 바탕으로 클라이언트에게 전달할 문서를 생성하는 흐름입니다.
1
판정 결과 화면에서 "리포트 생성하기" 버튼을 클릭한다
범위 내 / 부분 초과 / 범위 초과 / 판단 필요 전체에서 생성 가능.
2
Free 플랜 월 리포트 잔여 건수를 확인한다 (월 3건)
잔여 건수 없을 시 업그레이드 모달 표시.
3
시스템이 Claude API를 1회 호출하여 리포트 초안을 생성한다
  • 프롬프트 내 금지 표현 적용 ("죄송합니다", "유감입니다" 등 금지)
  • 생성 실패 시: 수동 작성 모드 전환 안내
4
리포트 초안이 표시된다
  • 구성: 프로젝트명 / 일시 / 요약 / 판정 결과 / 근거 / 비용 안내 / 견적 유효기간 / AI 면책 고지 / 법적 성격 안내
  • 편집 가능 영역: 추가 비용 금액, 안내 문구, 견적 유효기간
  • 편집 불가 영역: 판정 결과, 근거, 면책 고지, 법적 성격 안내 (고정 문구)
5
PM이 내용을 검토하고 "리포트 확정" 버튼을 클릭한다
직접 수정(PM 타이핑)과 "AI 재생성"은 이력에 구분 기록됩니다.
6
확정된 리포트가 DB에 저장되고 미리보기가 표시된다 (`version = 1`)
  • PDF 다운로드 버튼 활성화 (Flow 6)
  • Starter 이상: 이메일 발송 (Flow 7) 및 확인 링크 생성 버튼 (Flow 8) 활성화
7
PostHog에 `report_generated` 이벤트가 기록된다
⭐ AHA 모멘트 추적 완료
⚠️ 리포트 재생성 제한 정책
  • 리포트가 이메일 발송(sent) 상태인 경우 재생성 불가.
  • F-10 확인 링크로 클라이언트가 열람하거나 동의한 경우 재생성 불가.
Flow 6-7. 리포트 전달
Flow 6. PDF 다운로드
  • 리포트 확정 화면에서 "PDF 다운로드" 버튼을 클릭한다.
  • 브라우저 `window.print()` 실행 → PDF 저장 다이얼로그 표시.
  • 파일명 규칙: `[프로젝트명]_[클라이언트명]_범위판정리포트_[YYYYMMDD].pdf`
  • PostHog에 `pdf_downloaded` 이벤트 기록.
Flow 7. 이메일 발송 (Starter 이상)
  • 확정 화면에서 "이메일 발송" 버튼 클릭.
  • 클라이언트 이메일 자동 불러오기 + 발송 전 미리보기.
  • 이메일 본문: 요약 + PDF 첨부 + 확인 링크(생성된 경우).
  • 발송 완료 시 상태 "발송 완료" 변경. 편집 모드 잠금. 발송 이력 기록.
Flow 8. 클라이언트 확인 링크 & 동의 기록 (Starter 이상) ✨
클라이언트가 범위 초과 사실을 인지하고 동의했다는 타임스탬프를 남겨 분쟁을 방지합니다.
8-A. PM 측 — 확인 링크 생성 및 공유
  • 리포트 확정 후 "클라이언트 확인 링크 생성" 버튼 클릭. (Free 플랜은 업그레이드 모달)
  • 시스템이 `confirm_token`(UUID v4) 발급, 30일 만료.
  • PM이 생성된 링크(`https://[도메인]/confirm/[token]`)를 복사해 직접 공유.
  • PM 화면 배지: 미열람 → 열람 완료 → 동의 완료 (동의 시 인앱 알림).
  • 만료 토큰 재생성 가능. 단, 이미 동의된 리포트는 재생성 불가.
8-B. 클라이언트 측 — 확인 링크 접근 및 동의
  • 클라이언트가 링크에 접속 (가입 불필요, Public 라우트). 최초 접근 시 `first_viewed_at` 기록.
  • 확인 페이지 표시: 프로젝트명 / 요약 / 판정 결과 / 근거 / AI 면책 고지.
  • 하단 고정 문구: "이 동의는 인지 확인을 목적으로 하며 법적 구속력 있는 서명이 아닙니다."
  • 클라이언트가 "내용을 확인했습니다" 단일 버튼 클릭. (거절/협상 없음)
  • `confirmed_at`, `client_ip`, `user_agent` DB 기록. "담당 PM에게 전달됩니다." 메시지 표시.
  • PostHog `confirmation_agreed` 이벤트 기록.
Flow 9. 히스토리 타임라인 조회
  • 프로젝트 상세 페이지에서 "요청 히스토리" 탭을 클릭한다
  • 전체 판정 이력이 시간 순으로 표시된다. (일시 / 요약 / 결과 / 발송 여부 / 청구 상태 / 확인 상태)
  • 이미지 첨부 요청의 경우 썸네일 표시 — 클릭 시 원본 확인 (P1)
  • 판정 결과별 / 확인 상태별 / 기간별 필터 지원
  • 청구 상태 직접 변경: 미결정 → 청구 완료 / 청구 포기 / 무상 진행 선택 가능
Flow 10. 홈 대시보드 확인
1
로그인 직후 홈 대시보드(/)로 랜딩한다
2
프로젝트가 없는 경우
  • 빈 상태(Empty State) UI 표시
  • "첫 프로젝트 등록하기" CTA 버튼 노출 → Flow 3으로 이동
3
프로젝트가 있지만 판정 이력이 없는 경우
"첫 번째 클라이언트 요청을 판정해보세요" 안내 + 판정 입력 바로가기 버튼 표시
4
프로젝트와 판정 이력이 있는 경우
  • 기간 설정: 전체 누계 / 이번 달 / 최근 3개월
  • 핵심 수치 5개 카드: 진행 중 프로젝트 수, 추가 요청 건수, 청구 완료 건수, 방어 금액, 클라이언트 동의 완료 건수
  • 방어 금액: 청구 완료 건수 × 실제 청구 금액 합계 (계산 방식 툴팁 표시)
  • 손익 위험 프로젝트 목록 (적자 가능성 높은 순) 및 최근 판정 이력 5건 표시
Flow 11. 플랜 업그레이드
  • 기능 제한 모달 또는 설정의 "플랜 변경" 클릭 시 비교 화면 표시
  • "클라이언트 확인 링크 & 동의 기록" 기능이 Starter 혜택으로 강조 표시
  • "업그레이드" 클릭 → 결제 정보 입력 (토스페이먼츠 위젯)
  • 결제 완료 후 Webhook 수신 → `plan_type` 업데이트 + 사용량 즉시 리셋
  • PostHog `upgrade_modal_shown` → `plan_upgraded` 기록
  • 구독 해지 시: 당월 말까지 유지 후 다음 달 1일 Free 전환 (기존 데이터 유지, 신규 생성 제한)
