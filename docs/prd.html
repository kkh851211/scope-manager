1. 제품 개요
Scope Manager MVP v1.0 | 한국 웹 에이전시 PM을 위한 AI 범위 판정 내부 관리 도구
📌 1-1. 이 문서의 목적과 사용 방법

이 PRD(Product Requirements Document)는 Scope Manager MVP를 만드는 데 필요한 모든 기능 요구사항, 우선순위, 포함/제외 범위, 완료 기준 및 운영 정책을 통합 정의한다.

누가 이 문서를 사용하는가: 현재 유일한 빌더인 Jey(PM 겸 기획자)가 Antigravity(AI IDE)에 프롬프트를 작성할 때 기준 문서로 활용한다. 기능 범위나 우선순위, 정책 결정이 필요할 때 이 문서로 돌아온다.

다른 기획 문서와의 관계: 린캔버스(Why), 사용자 리서치(Who), 제품 비전(What & How)이 이미 완성되어 있으며, 이 PRD는 그 위에서 구체적으로 무엇을 어떤 순서로 만드는가를 정의한다.

⚠️ 2. 전제 조건 및 제약사항
✅ 2-1. 전제 조건 (Assumptions)
  • 타겟 에이전시 PM은 기존 계약서·범위 정의 문서를 보유하고 있다
  • 계약서가 없는 경우(구두 계약 등) 시스템 진입 자체를 차단하고, "계약 범위를 직접 작성" 가이드 UI를 제공한다 — 프리랜서 특화는 P3로 연기
  • 클라이언트 추가 요청은 텍스트로 표현 가능한 형태로 들어온다
  • PM은 판정 결과를 직접 클라이언트에게 전달하는 역할을 유지한다
  • 초기 사용자는 데스크톱 브라우저로 접속한다
  • Supabase / Vercel / Claude API 서비스가 안정적으로 운영된다
  • MVP는 한국어 전용으로 시작한다 (다국어 불필요)
🚧 2-2. 제약사항 (Constraints)
  • 기술 스택 고정 — Next.js 14 + Supabase + Claude API + Vercel (변경 불가)
  • 비개발자 빌더 — Antigravity AI IDE 의존, 복잡한 커스텀 인프라 불가
  • MVP 예산 제한 — Claude API 호출 비용 최소화 필수 (Fast Path 전략)
  • 데스크톱 우선 — 태블릿·모바일 반응형은 v1.1로 연기
  • 1인 개발 — 동시 다발적 기능 개발 불가, 순차 빌드 필수
  • 클라이언트 대면 기능 금지 — 내부 도구 원칙 (철회 불가)

영역 ① — 인증 & 멀티테넌트 (Auth & Multi-tenant)
P0
F-01 이메일 / 소셜 로그인
사용자 스토리
PM 또는 에이전시 대표로서, 이메일 또는 구글 계정으로 빠르게 가입·로그인하고 싶다. 그래야 추가 설정 없이 바로 프로젝트를 등록할 수 있다.
기술 노트
  • Supabase Auth 사용 — 이메일+패스워드 / Google OAuth
  • 가입 시 `organizations` 테이블에 워크스페이스 자동 생성
  • JWT 토큰 기반 세션 관리 (Supabase 기본 제공)
  • 이메일 인증 확인 후 온보딩 플로우 진입
세부 요구사항
  • 이메일 + 패스워드 회원가입 / 로그인 / 비밀번호 재설정 구현
  • Google OAuth 소셜 로그인 지원 (Supabase Auth Provider)
  • 가입 완료 시 워크스페이스(organization) 자동 생성 및 사용자-워크스페이스 연결
  • 미인증 상태에서 보호 경로 접근 시 /login으로 리다이렉트
  • 로그인 상태 유지 (Remember me) — 기본 7일
  • 가입 후 온보딩 플로우 진입 — 빈 상태 대시보드 + "첫 프로젝트 만들기" CTA 표시
F-02 워크스페이스 격리 & RLS 기반 데이터 보호 ⚠️ 보안 필수
사용자 스토리
에이전시 대표로서, 우리 회사의 계약서·판정 기록·손익 데이터가 다른 에이전시에게 절대 노출되지 않아야 한다. 고객 정보 유출은 비즈니스 리스크다.
기술 노트
  • 모든 테이블에 organization_id UUID NOT NULL 컬럼 필수
  • Supabase RLS Policy: SELECT/INSERT/UPDATE/DELETE 전체에 적용
  • Claude API 호출 시 프롬프트에 타 테넌트 데이터 미포함 검증 필수
  • Supabase 쿼리에 RLS 의존만 하지 않고 WHERE organization_id = ? 명시 추가
세부 요구사항
  • 모든 DB 테이블에 RLS 활성화 — organization_id 기반 row 접근 제어
  • 사용자는 자신이 속한 organization의 데이터만 조회·수정·삭제 가능
  • API Route 레벨에서도 organization_id 검증 이중화
  • Claude API 프롬프트 구성 시 해당 organization 데이터만 컨텍스트로 주입
  • QA: 다른 organization 계정으로 데이터 접근 시도 → 403 반환 확인

영역 ② — 핵심 기능 (Core Features)
P0
F-03 프로젝트 생성 및 계약 범위 등록
사용자 스토리
PM으로서, 새 프로젝트를 만들고 계약서의 범위 내용을 텍스트로 입력해 등록하고 싶다. 그래야 클라이언트 요청이 왔을 때 AI가 이 기준으로 판정해줄 수 있다.
기술 노트
  • DB 테이블: `projects`, `scope_definitions`
  • 계약 범위 텍스트 → Claude API로 구조화 파싱 (1회 호출, 캐시)
  • 파싱 결과를 `scope_definitions`에 JSON으로 저장
  • 이후 판정 시 재파싱 없이 저장된 구조체 재사용 → API 비용 절감
세부 요구사항
  • 프로젝트명 / 클라이언트명 / 계약 시작일 / 계약 금액 입력 폼
  • 계약 범위 텍스트 자유 입력 (textarea, 최대 5,000자)
  • 계약서가 없는 경우: 시스템 진입 차단 + "계약 범위 직접 작성 가이드" 팝업 표시 (가이드 양식 제공)
  • 범위 등록 완료 시 Claude API로 구조화 파싱 1회 실행 → 항목 리스트로 변환
  • 파싱된 항목 목록 PM이 확인·수정 가능한 미리보기 UI
  • 프로젝트 상태: 진행 중 / 완료 / 보류 3단계
  • 프로젝트 목록 페이지 — 최신순 정렬, 상태 필터
F-04 클라이언트 요청 입력 및 AI 범위 판정 ⭐ AHA 모멘트 직전
사용자 스토리
PM으로서, 클라이언트의 추가 요청을 입력하면 AI가 30초 안에 계약 범위와 비교해서 "범위 내 / 초과 / 판단 필요" 중 하나로 판정해주길 원한다. 내가 직접 판단하지 않아도 된다.
세부 요구사항
  • 클라이언트 요청 내용 텍스트 입력 (최대 2,000자)
  • 판정 결과 3단계: 범위 내 판단 필요 범위 초과
  • "판단 필요" 케이스 후속 플로우: PM이 수동으로 최종 판정 선택 → DB에 오버라이드 기록 저장 → 이후 Fast Path 캐시 우선 적용
  • 판정 근거 표시 — 계약서 어느 항목과 비교했는지 근거 문장 출력
  • 판정 소요 시간 목표: 30초 이내 (스트리밍 응답)
  • 판정 결과 저장 — 히스토리 자동 누적, PM 동의/재판정 기능
  • Free 플랜 제한: 월 판정 10회 — 초과 시 업그레이드 유도 모달 표시
⚡ 기술 노트 — Fast Path 로직 & 에러 핸들링
[Fast Path 적중 조건]
① 완전 일치: 코사인 유사도 ≥ 0.92 → 범위 내 반환
② 명백한 신규: 최대 유사도 ≤ 0.35 → 범위 초과 반환
③ 중복 요청: scope_requests 캐시에서 동일 해시(SHA-256) 발견 → 결과 재사용
④ PM 오버라이드 패턴: 이전 PM 직접 판정 패턴과 유사도 ≥ 0.88 → 기록 우선 적용

[Claude 호출 조건 (0.35 < 유사도 < 0.92)]
① 애매한 요청 ② 복합 요청 ③ 신규 카테고리 (목표: 30~40% Fast Path 처리)

[에러 핸들링]
- 타임아웃(30초 초과): 재시도 1회 → 실패 시 "일시적 오류" 메시지 + 수동 판정 모드 제공
- 연속 실패(2회): 수동 판정 모드 자동 전환 + "AI 판정 일시 중단" 배너 표시
- Supabase 오류: 로컬 스토리지 임시 저장 후 복구 시 동기화
- 브라우저 새로고침: status 컬럼(pending/completed/failed)으로 상태 복원
F-05 판정 결과 리포트 자동 생성 ⭐ AHA 모멘트 (전환 트리거)
사용자 스토리
PM으로서, 범위 초과 판정 결과를 클라이언트에게 보낼 수 있는 공식 문서 형태로 자동 생성해주길 원한다. 내가 직접 문구를 쓰지 않고, 시스템 어조의 중립적 리포트를 받고 싶다.
기술 노트
  • 판정 후 리포트 생성은 별도 Claude API 호출 1회
  • 리포트 언어: 한국어, 중립적 시스템 어조 강제
  • 프롬프트 내 금지 표현 삽입: "죄송합니다", "유감입니다" 등 감정/사과 언어 일체 금지
  • 생성된 리포트 HTML/텍스트로 DB 저장
  • PDF 변환: 브라우저 window.print() 우선 사용
세부 요구사항
  • 리포트 구성: 프로젝트명 / 요청 일시 / 요청 내용 요약 / 판정 결과 / 계약 근거 / 추가 비용 안내 문구
  • PM이 리포트 내용 수정 후 확정 가능 (편집 모드)
  • 리포트 미리보기 — 클라이언트가 받게 될 형태로 렌더링
  • PDF 다운로드 버튼 (P0 MVP 구현)
  • Free 플랜 제한: 월 리포트 3건 — 초과 시 Starter 업그레이드 유도 모달
F-06 이메일 발송 / PDF 다운로드 P1 (Starter)
사용자 스토리
PM으로서, 생성된 리포트를 클라이언트 이메일로 직접 발송하거나 PDF로 다운로드해서 첨부 파일로 보내고 싶다.
세부 요구사항
  • 클라이언트 이메일 주소 입력 후 1클릭 발송
  • 발송 전 미리보기 확인 단계 필수 (실수 방지)
  • PDF 다운로드 — 리포트 확정 후 버튼 활성화
  • 발송 완료 후 리포트 상태 → "발송 완료"로 변경
  • 자동 발송 없음 — PM 수동 클릭 필수

운영 정책 & 결제 로직
제품 운영에 필수적인 정책, 다운그레이드 처리, 에러 메시지 및 스트리밍 UX를 정의합니다.
10-1. 사용량 초기화 정책
  • Free 플랜 월 사용량(판정 10회 / 리포트 3건)은 매월 1일 자정(KST 00:00) 초기화
  • DB 구현: `organizations` 테이블에 `usage_reset_at` 컬럼 필수
  • 초기화는 서버 사이드 스케줄러(Supabase Edge Function cron 또는 Vercel Cron Jobs)로 처리
  • 유료 플랜 전환 시 사용량 카운터 즉시 리셋
10-2. 소프트 게이트 차단 정책
  • Free 한도 초과 후 업그레이드 모달을 닫으면 → 해당 기능 완전 차단
  • 모달을 닫아도 월말까지 차단 상태 유지 (기능 버튼 disabled 상태 렌더링 + 툴팁)
  • 이미 생성 완료된 리포트 조회·PDF 다운로드는 차단 제외
10-3. 데이터 삭제 정책 (Soft Delete)
  • 프로젝트 삭제 시 Soft delete 처리 — DB 즉시 제거 없이 `deleted_at` 기록
  • 삭제된 프로젝트의 하위 데이터(이력, 리포트 등)도 동시 Soft delete
  • 삭제 후 30일 이내 복구 가능 (UI P2), 30일 경과 후 Hard delete 스케줄러 자동 실행
  • RLS 정책에 `deleted_at IS NULL` 조건 추가 필수
10-4 & 5. 리포트 수정 및 재생성
  • 이메일 발송 완료 시 리포트 상태 `sent`로 변경 + 편집 모드 잠금 (불일치 방지). PDF 다운로드는 가능.
  • 판정 결과 수동 오버라이드 시 리포트 자동 재생성 + 토스트 알림 표시. (이전 버전 덮어씀)
  • 이미 발송(sent) 상태인 리포트는 재생성 대상 제외 → 경고 모달 표시.
10-6. Fast Path 캐시 무효화 정책
  • `scope_definitions` 수정 시 → 해당 프로젝트의 Fast Path 캐시 전체 자동 무효화 (`cache_valid` false 처리)
  • 단, PM 오버라이드 패턴 캐시는 범위 수정과 무관하게 유지 (명시적 판단 존중)
10-7 & 8. 면책 고지 & 개인정보 처리
  • 리포트 하단 및 PDF에 AI 면책 고지 고정 문구 필수 (수정 불가).
  • 설정 페이지 "계정 삭제" 버튼 필수. 탈퇴 시 즉시 차단 + 30일 후 Hard delete.
  • PostHog 이벤트에 개인/계약 데이터 절대 미포함 (식별자, 플랜, 타임스탬프만 전송).
💳 11-2. 결제 정책 (토스페이먼츠) & 11-3. 다운그레이드
  • 결제 주기 및 수단: 월간 구독, 토스페이먼츠 자동결제 연동. Next.js API Route에서 시크릿 키 안전 처리.
  • 결제 플로우: 업그레이드 모달 → 토스페이먼츠 위젯 렌더링 → 결제 승인 Webhook → `plan_type` 업데이트 & 사용량 리셋.

  • 다운그레이드 정책: 기존 데이터 전체 유지(삭제 없음). 초과 데이터는 조회만 가능, 신규 생성/편집 차단. UI 배너 표시.
