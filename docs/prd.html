📌 1-1. 이 문서의 목적과 사용 방법

이 PRD는 Scope Manager MVP를 만드는 데 필요한 모든 기능 요구사항, 우선순위, 포함/제외 범위, 완료 기준 및 운영 정책을 통합 정의한다.

누가 사용하는가: 현재 유일한 빌더인 Jey(PM 겸 기획자)가 Antigravity(AI IDE)에 프롬프트를 작성할 때 기준 문서로 활용한다.
다른 기획 문서와의 관계: 린캔버스(Why), 사용자 리서치(Who), 제품 비전(What & How)이 이미 완성되어 있으며, 이 PRD는 구체적으로 무엇을 어떤 순서로 만드는가를 정의한다.

문서 핵심 질문 PRD와의 관계
린캔버스 (Why) 왜 만드는가 수익 모델(Free/Starter/Pro)과 AARRR 지표가 PRD 비즈니스 목표 기준
사용자 리서치 (Who) 누구를 위한가 페르소나 3인의 고통점·JTBD가 기능 요구사항의 근거. AHA 모멘트 = 첫 리포트 생성
제품 비전 (What) 어떤 제품인가 What We Build / Don't Build / Design Principles가 포함·제외 판단 기준

  • 6개월 MRR 870,000원 (Starter 30개) — 손익분기점

  • 에이전시 커뮤니티 레퍼럴을 통한 자연 성장 채널 확보
  • PostHog 데이터로 PMF 신호 조기 포착
👤 사용자 목표
  • 클라이언트 요청 수신 후 30초 내 판정 결과 확인
  • PM이 직접 말하지 않고 리포트로 비용 청구 근거 전달
  • 클라이언트 인지·동의 타임스탬프 기록으로 분쟁 대응
  • 프로젝트 진행 중 실시간 손익 파악 가능
  • 첫 리포트 생성 후 AHA 모멘트 경험
  • 범위 협상에서 개인 책임 부담 감소
🛠 기술 목표
  • Next.js 단일 스택으로 Python/FastAPI 없이 Claude API 연동
  • Supabase RLS로 멀티테넌트 데이터 완전 격리
  • Claude API Temperature 0.2 — 판정 일관성 확보
  • Fast Path 로직으로 API 호출 비용 최소화
  • 확인 링크 — 클라이언트 가입 불필요한 서명 토큰(UUID) 방식
  • Vercel 서버리스 배포로 인프라 관리 제로
⚠️ 2. 전제 조건 및 제약사항
✅ 2-1. 전제 조건 (Assumptions)
  • 타겟 에이전시 PM은 기존 계약서·범위 정의 문서를 보유하고 있다. (없으면 진입 차단 + 가이드 제공)
  • 클라이언트 추가 요청은 텍스트 또는 이미지 형태로 들어온다.
  • PM은 판정 결과를 직접 클라이언트에게 전달하는 역할을 유지한다. (도구 사용 여부 공개는 PM 재량)
  • 시스템은 계약서의 법적 유효성이나 완결성은 검증하지 않는다.
  • 클라이언트 확인 링크 동의는 법적 구속력 있는 서명이 아닌 인지 확인 수준이다.
  • MVP는 한국어 전용으로 시작한다.
🚧 2-2. 제약사항 (Constraints)
  • 기술 스택 고정 — Next.js 14 + Supabase + Claude API + Vercel (변경 불가)
  • 비개발자 빌더 — Antigravity AI IDE 의존, 복잡한 커스텀 인프라 불가
  • MVP 예산 제한 — Claude API 호출 비용 최소화 필수 (Fast Path 전략)
  • 데스크톱 우선 — 모바일 반응형은 v1.1 연기. 단, 확인 링크 페이지는 모바일 대응 필수.
  • 1인 개발 — 동시 다발적 기능 개발 불가, 순차 빌드 필수
  • 클라이언트 대면 기능 금지 — (내부 도구 원칙) F-10 확인 링크만 예외 허용.

영역 ② — 핵심 기능
P0
F-03 프로젝트 생성 및 계약 범위 등록
세부 요구사항
  • 정보 폼: 프로젝트명 / 클라이언트명 / 클라이언트 이메일 / 계약 시작일 / 계약 종료일 / 계약 금액 / 금액 유형(고정/유지보수)
  • 범위 텍스트 5,000자 입력 (P1: 파일 업로드)
  • 계약서 없는 경우 시스템 진입 차단 + 가이드 제공
  • 입력 이탈 시 임시저장 지원
  • 완료 시 Claude API 파싱(1회) → 수정 가능한 목록 미리보기. 수정된 `parsed_items`가 최종 판정 기준.
기술 노트
  • 파싱 실패 시 수동 입력 모드 전환
  • 계약 범위 수정 시 버전(version) 증가, 이전 판정 이력은 구버전 기준 유지.
  • 수정 시 Fast Path 캐시 전체 자동 무효화
F-04 클라이언트 요청 입력 및 AI 범위 판정 ⭐ AHA 모멘트 직전
세부 요구사항
  • 텍스트 2,000자 입력 (P1: 이미지 최대 3장 첨부)
  • 결과 4단계: 범위 내 부분 초과 범위 초과 판단 필요
  • 부분 초과: 일부 항목만 초과인 경우 분리 표시.
  • "판단 필요" 시 PM 수동 판정 → DB 오버라이드 기록 저장
  • 근거 문장 및 예상 추가 공수 참고치 표시
  • 중복 요청 감지 시 모달 안내, 재판정 기능 제공
  • 판정 취소(기록 안함) 가능 (단, Free 횟수 차감)
기술 노트 (Fast Path)
  • ① 코사인 유사도 ≥ 0.92: 이전 결과 재사용
  • ② 최대 유사도 ≤ 0.35: 범위 초과 반환
  • ③ SHA-256 해시 매칭: 중복 캐시 활용
  • ④ PM 오버라이드 유사도 ≥ 0.88: 기록 우선
  • Claude 호출 조건: 0.35 < 유사도 < 0.92 (애매/복합/신규)
  • 타임아웃(30초) 시 1회 재시도, 연속 실패 시 수동 모드
F-05 판정 결과 리포트 자동 생성 ⭐ AHA 모멘트
세부 요구사항
  • 구성: 프로젝트명 / 일시 / 요약 / 판정 결과 / 근거 / 비용 안내 / 유효기간 / AI 면책 고지 / 법적 성격 안내
  • 편집 가능: 추가 비용 금액, 안내 문구, 유효기간(기본 14일)
  • 편집 불가: 판정 결과, 근거, 면책 고지 등
  • PM 직접 수정과 AI 재생성 이력 구분 기록
  • 생성 실패 시 수동 작성 모드, F-10 동의 시 재생성 차단
기술 노트
  • Claude API 1회 호출. 한국어 중립적 시스템 어조 강제
  • 프롬프트 금지어("죄송합니다" 등 감정/사과) 필수 적용
  • PDF 변환: window.print() 우선 (P1 서버사이드 검토)
F-06 이메일 발송 / PDF P1
  • 클라이언트 이메일 자동 불러오기 + 1클릭 발송
  • 본문 요약 + PDF 첨부 + F-10 링크 포함
  • 미리보기 필수. 자동 발송 없음 (PM 수동 클릭)
  • 발송 완료 시 편집 모드 잠금
  • SendGrid API 사용 (Vercel 환경변수 관리)
F-10 클라이언트 확인 링크 (동의) P1 신규
  • 리포트 확정 후 `confirm_token` (UUID v4) 발급. 30일 유효
  • 외부 공개용 `/confirm/[token]` 페이지 제공 (가입 불필요)
  • "내용을 확인했습니다" 단일 버튼. 거절/협상 없음
  • 동의 시 `confirmed_at`, IP, UA 기록 + PM 인앱 알림
  • 법적 서명이 아닌 인지 확인용 (고정 문구 안내)

🚀 4. 온보딩 플로우 (10단계)
단계 화면/상태 PM 액션 / 시스템 동작 PostHog 이벤트
① 가입 완료 Auth 이메일 인증 / organization 자동 생성 `user_signed_up`
② 빈 대시보드 Empty State "첫 프로젝트 만들기" CTA + 3단계 안내 표시 `dashboard_viewed_empty`
③ 프로젝트 생성 Core 입력 폼 + 계약 범위 / Claude 파싱 / 임시저장 `project_created`
④ 범위 확인 Core AI 구조화 항목 확인 및 수정 / DB 저장 `scope_confirmed`
⑤ 첫 판정 요청 Core 클라이언트 요청 입력 / Fast Path or Claude 판정 `first_scope_judgment`
* 온보딩 완료 기준
⑥ 결과 확인 Core 4단계 결과 + 근거 문장 확인 `judgment_result_viewed`
⑦ 리포트 생성 AHA 모멘트 초안 생성 및 편집 `report_generated`
* Free→Paid 트리거
⑧ PDF 다운로드 PDF PDF 변환 다운로드 `pdf_downloaded`
⑨ 확인 링크 생성 P1 신규 `confirm_token` 생성 및 링크 복사 `confirmation_link_created`
⑩ 클라이언트 동의 P1 신규 동의 배지 + 타임스탬프 기록 `confirmation_agreed`

🔲 7. 범위 정의 (In vs Out of Scope)
✅ In Scope — MVP에 포함
  • 인증, 워크스페이스 생성, RLS 데이터 보호
  • 프로젝트 생성, 범위 등록 및 버전 관리
  • 요청 입력, AI 범위 판정 (Fast Path 포함, 4단계 결과)
  • 복합 요청 부분 초과 처리 및 근거 표시

🛡️ 11. 운영 정책 요약
사용량 & 소프트 게이트
  • 초기화: 매월 1일 자정(KST) 스케줄러를 통해 초기화. (재판정도 횟수 차감)
  • 차단: 한도 초과 시 모달 제공, 닫으면 버튼 disabled 처리 (소프트 게이트).
데이터 관리 (Soft Delete & 캐시)
  • Soft Delete: 삭제 시 `deleted_at` 기록. 30일 후 Hard delete. `confirmed_at`이 있는 리포트는 삭제 제외 (증거 보존).
  • 캐시 무효화: 계약 범위 수정 시 해당 Fast Path 캐시 무효화. 단, PM 오버라이드 캐시는 유지.
리포트 수정 & 확인 링크
  • 수정 제한: 발송 완료 시 `sent` 상태 변경 및 편집 잠금. 오버라이드 시 자동 재생성(발송된 건 제외).
  • 확인 링크: 30일 만료. 재생성 가능(이전 무효화). 열람/동의 시 수정 불가. 하단 AI 면책 고지 고정.
결제 & 다운그레이드 (토스페이먼츠)
  • 결제: 토스페이먼츠 정기결제. 해지 시 월말까지 유지 후 Free 전환.
  • 다운그레이드: 데이터 전체 유지(삭제 없음), 초과 데이터는 조회만 허용.
