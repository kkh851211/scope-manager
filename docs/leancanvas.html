린캔버스 I — 문제와 해결책
Scope Manager의 비즈니스 모델을 9개 블록으로 요약한 린캔버스입니다. [Image of Lean Canvas business model]
01 — Problem · 해결할 문제
핵심 문제 3가지
  • 청구 포기 구조 — "돈 달라는 말을 꺼내기 어렵다"는 심리적 장벽이 반복적 손실로 이어짐. 범위 초과 청구 포기율 68%
  • AI 인식 격차 — 클라이언트는 "AI가 다 해주니 싸야 한다", 에이전시는 "AI 검증 비용이 새로 생겼다"
  • 표준 부재 — 변경 관리 단가의 업계 표준이 없어 협상이 PM 개인의 담력에 의존
기존 대안과 한계
  • 카카오톡 + 엑셀 — 기록은 있으나 판정·근거 생성 불가
  • Jira / Asana / Notion — 과업 관리 목적, 범위 초과 청구 설계 없음
  • 엔터프라이즈 CM 도구 — 고비용·복잡, 5~20인 에이전시 현실과 괴리
PMI 통계: 프로젝트 52% 스코프 크리프 경험 / 예산 초과율 85% / 평균 초과 27%
02 — Solution · 솔루션
핵심 해결책
  • 범위 초과 자동 판정 — 계약 범위 대비 자동 비교. Fast Path 로직으로 30~40% 케이스는 API 호출 없이 즉시 처리
  • 청구 근거 자동 생성 — "시스템상 과업 범위를 초과한 것으로 기록되었습니다"라는 문장을 도구가 자동 생성. PM은 전달만 한다
  • 프로젝트 손익 누적 기록 — 프로젝트별 실제 손익을 누적 기록하여 다음 견적·계약의 기준을 데이터로 만든다
린캔버스 II — 가치 제안과 고객
제품의 고유한 가치와 타겟 고객층을 정의합니다.
03 — Unique Value Proposition · 핵심 가치 제안
"PM이 아쉬운 소리 하지 않아도 범위 초과 비용을 받아낼 수 있는 구조"

기존 PM 도구가 과업 '관리'에 집중했다면, Scope Manager는 관계 보호 + 수익 방어에 집중한다.
"제가 그러는 게 아니라, 시스템이 범위를 벗어났다고 판정했습니다" — PM의 감정 노동 없이 데이터가 협상한다.

포지셔닝 차별화
  • 타겟 특화 — 5~20인 에이전시 PM만을 위한 전용 설계
  • 역할 전환 — PM의 감정 노동을 시스템의 데이터 판정으로 대체
  • 협상 구조 변화 — "개인 요청"에서 "시스템 판정 결과"로 프레임 전환
  • 누적 가치 — 사용할수록 더 정확한 업계 단가 기준 형성
  • 클라이언트 대면 기능 없음 — 내부 도구 원칙 고수. 리포트는 PM이 전달 주체
04 — Unfair Advantage · 경쟁 우위
  • 도메인 전문성 — PM 현장 경험에서 나온 페인포인트 설계
  • 전용 포지셔닝 — 범용 PM 도구가 진입하기 어려운 "청구 협상" 특화
  • 데이터 네트워크 효과 — 누적 프로젝트 데이터 → 업계 단가 기준 → 신규 고객 유인
  • First Mover — 국내 에이전시 변경 관리 SaaS 공백 시장 선점
  • PM 오버라이드 학습 — PM이 직접 판정한 패턴이 누적될수록 Fast Path 정확도 향상
05 — Customer Segments · 고객 세그먼트
  • 핵심 (MVP) 5~20인 웹 에이전시 PM. 프로젝트 1개 적자가 회사 현금흐름에 직접 영향
  • 얼리어답터 PM 겸직 대표. 문제 인식 + 결제 권한 모두 보유
  • 확장 (Phase 2) 프리랜서 개발자·디자이너, 소규모 IT 컨설팅사 (에이전시 PMF 검증 후 별도 JTBD 검증 필요)
  • 제외 5인 미만(체계 불필요), 20인 초과(자체 해결책 보유)
비즈니스 — 지표, 채널, 수익, 비용
제품의 성장 지표와 채널, 그리고 수익 모델 및 비용 구조를 정의합니다.

MVP 우선 검증 전략
전통적인 린 스타트업 방법론을 AI 시대에 맞게 재설계했습니다.
💡 전략적 선택 — 고객 인터뷰 → MVP 순서 역전

AI 개발 도구의 발달로 MVP 제작 비용과 시간이 극적으로 낮아졌다. 불확실성이 높은 인터뷰를 생략하고 MVP를 즉시 배포하여 실제 행동 데이터로 가설을 검증하는 전략을 선택했다.

역전 전략의 논리
  • 말 vs 행동 불일치 — 인터뷰의 intention과 실제 behavior는 다르다
  • 비용 역전 — AI 덕분에 MVP 개발 비용 < 인터뷰 설계/진행 비용
  • 신호의 정직성 — 사용/이탈 패턴이 인터뷰보다 더 정직한 검증 신호
  • 속도 우위 — "만들어서 보여주는" 것이 "물어보는" 것보다 빠름
검증할 핵심 가설
  • PM의 추가 비용 청구 포기율이 > 60% 인가?
  • 시스템 판정 결과를 클라이언트가 수용하는가?
  • Free → Paid 전환을 유발하는 AHA 모멘트는 "첫 리포트 생성"인가? (단일 트리거)
  • 29,000원/월 가격에 지불 의향이 존재하는가?
