01

문서 목적 및 범위

이 문서는 Scope Manager(스코프 매니저) 서비스의 운영 기준, 기능 정책, 데이터 처리 원칙, 결제 규칙을 명문화한 내부 정책서다. PRD v2.1에서 기술된 기능 요구사항을 보완하며, PRD가 "무엇을 만드는가"를 정의한다면 이 문서는 "어떤 규칙으로 작동하는가"를 정의한다.

본 정책서의 적용 대상은 Scope Manager 서비스를 사용하는 모든 에이전시 조직(Organization)과 PM 사용자이며, 서비스 운영자(Jey / 개발 주체)의 내부 의사결정 기준으로도 활용된다.

ℹ
적용 우선순위: 이 정책서의 내용과 PRD가 충돌하는 경우, 이 정책서가 최신 기준으로 우선 적용된다. 단, 기술 구현 세부사항은 PRD의 기술 노트를 따른다.
02

용어 정의

Organization
하나의 에이전시 단위로 생성되는 워크스페이스. 가입 시 자동 생성되며, 모든 데이터는 Organization 단위로 격리된다.
PM 사용자
Scope Manager에 가입하여 프로젝트를 관리하고 AI 판정을 실행하는 에이전시 내부 사용자. 클라이언트와 구분된다.
클라이언트
에이전시의 발주 고객. Scope Manager에 가입하지 않으며, 확인 링크(UUID 토큰)를 통해 특정 페이지에만 접근한다.
계약 범위
PM이 프로젝트에 등록한 계약서 내용. AI 판정의 기준이 되며, PM이 수정·확정한 parsed_items가 실제 판정 기준으로 사용된다.
사전 동의
프로젝트 시작 전 클라이언트가 계약 범위를 확인하고 동의한 기록 (F-03-S). 법적 서명이 아닌 인지 확인 수준.
사후 인지
추가 요청 판정 후 클라이언트가 리포트 내용을 확인하고 동의한 기록 (F-10). 분쟁 대비 증거 기록 목적.
Fast Path
코사인 유사도 기반의 사전 판정 로직. Claude API 호출 없이 결과를 반환하여 비용을 절감하는 내부 최적화 메커니즘.
소프트 게이트
플랜 한도 초과 시 업그레이드 모달을 표시하고, 모달을 닫으면 해당 기능을 차단하는 UX 패턴.
03

계정 및 조직 정책

3-1. 가입 및 워크스페이스 생성
  • 가입 수단은 이메일+패스워드 및 Google OAuth 두 가지로 제한한다.
  • 이메일 가입 시 이메일 인증 완료 후 서비스 이용이 가능하다.
  • 가입 완료 시 Organization(워크스페이스)이 자동으로 1개 생성된다. 1인 1 Organization을 원칙으로 하며, 복수 Organization 생성은 지원하지 않는다.
  • 가입 즉시 Free 플랜이 적용된다. 별도 카드 등록 없이 사용 가능하다.
3-2. 역할 및 권한

MVP 단계에서는 단일 사용자(Admin) 체제로 운영된다. 팀원 초대 및 멀티 유저 기능은 Pro 플랜 P2 단계에서 지원 예정이다.

역할권한 범위지원 시점
Admin (단독)전체 기능 접근, 플랜 관리, 결제, 데이터 삭제MVP
Member프로젝트 생성, 판정, 리포트 생성 (결제·삭제 제외)Pro P2
3-3. 계정 삭제 및 탈퇴
  • PM 사용자는 설정 페이지에서 언제든지 계정 삭제를 요청할 수 있다.
  • 삭제 요청 즉시 로그인이 차단된다. 모든 데이터는 Soft delete 처리된다.
  • 삭제 요청일로부터 30일 이내에는 복구 요청이 가능하다 (P2 UI 예정. 현재는 운영자 직접 처리).
  • 30일 경과 후 모든 데이터가 Hard delete된다. 단, scope_confirmed_at 또는 confirmed_at이 기록된 행은 삭제 불가 — 증거 보존 원칙 우선 적용.
  • 유료 구독 중 탈퇴 시 당월 말까지 유료 기능 유지 후 자동 종료된다. 잔여 기간 환불은 제공하지 않는다.

  • 월 사용량은 매월 1일 자정 KST 00:00에 초기화된다.
  • 유료 플랜 전환(Free → Starter, Starter → Pro) 시 사용량 카운터가 즉시 리셋된다.
  • 다운그레이드(Pro → Starter, Starter → Free) 시 사용량은 유지되며, 새 플랜 한도 기준으로 다음 달 1일부터 적용된다.
  • 초기화는 Supabase Edge Function cron 또는 Vercel Cron Jobs로 자동 처리된다.
4-4. 한도 초과 시 동작 (소프트 게이트)
  • 한도 초과 시 업그레이드 유도 모달이 표시된다. 모달을 닫으면 해당 기능이 월말까지 완전 차단된다.
  • 이미 생성 완료된 리포트 조회 및 PDF 다운로드는 한도 초과와 무관하게 항상 허용된다.
  • AI 파싱 한도 초과 시에도 수동 범위 입력 모드는 항상 제한 없이 사용 가능하다.
4-5. 다운그레이드 시 데이터 처리
  • 다운그레이드 후에도 기존 데이터(프로젝트, 판정 이력, 리포트)는 전부 유지된다.
  • 새 플랜 한도를 초과하는 신규 생성/편집은 차단된다.
  • UI 상단에 "플랜이 변경되었습니다" 배너를 표시한다.

5-2. Fast Path 분기 정책

Fast Path는 Claude API 호출 비용을 절감하기 위한 내부 최적화 로직이다. 전체 요청의 30~40% Fast Path 처리를 목표로 한다.

경로조건동작
Fast Path A코사인 유사도 ≥ 0.92이전 판정 결과 재사용 (범위 내 고정 반환 아님)
Fast Path B최대 유사도 ≤ 0.35범위 초과 반환. 단, 포괄적 계약서 오판 가능성 있음.
Fast Path C동일 요청 해시(SHA-256) 감지PM에게 확인 모달 → 결과 재사용 또는 새 판정
Fast Path DPM 오버라이드 패턴과 유사도 ≥ 0.88오버라이드 기록 우선 적용
Claude API 호출0.35 < 유사도 < 0.92실제 Claude API 범위 판정 실행
  • 계약 범위(scope_definitions) 수정 시 해당 프로젝트의 Fast Path 캐시가 전체 자동 무효화된다.
  • PM 오버라이드 패턴 캐시는 범위 수정과 무관하게 유지된다.
5-3. AI 판정 결과의 법적 성격
!
면책 고지 (변경 불가 고정 문구): Scope Manager의 AI 판정 결과는 참고 목적으로만 제공되며, 법적 효력을 가지지 않습니다. 최종 판단 및 클라이언트 커뮤니케이션의 책임은 PM에게 있습니다.
  • AI 판정 결과는 PM의 의사결정을 보조하는 참고 자료이며, 법적 구속력이 없다.
  • PM은 AI 판정 결과를 오버라이드할 수 있으며, 오버라이드 기록은 DB에 별도 저장된다.
  • 판정 근거 문장은 PM이 어떤 계약 항목과 비교되었는지 확인할 수 있도록 출력된다.
  • AI 면책 고지는 리포트, PDF, 클라이언트 확인 페이지 모두에 고정 표시되며 편집할 수 없다.
5-4. 판정 실패 및 타임아웃 처리
  • 판정 요청 30초 초과(타임아웃) 시 재시도 1회를 자동 실행한다.
  • 재시도까지 실패(연속 2회 실패) 시 수동 판정 모드로 자동 전환되며, "AI 판정 일시 중단" 배너가 표시된다.
  • 판정 결과 저장 전 Supabase 오류 발생 시 로컬스토리지에 임시 저장 후 복구 시 동기화한다.
5-5. 리포트 생성 및 수정 정책
  • 리포트는 중립적 시스템 어조로 생성된다. "죄송합니다", "유감입니다" 등 감정·사과 표현은 프롬프트 수준에서 금지된다.
  • 편집 가능 영역: 추가 비용 금액, 안내 문구, 견적 유효기간.
  • 편집 불가 영역(고정): 판정 결과, 계약 근거, AI 면책 고지, 동의의 법적 성격 안내, 클라이언트 범위 확인 상태 문구.
  • 이메일 발송 완료(sent 상태) 후 편집 모드 잠금. PDF 다운로드는 발송 후에도 가능.
  • F-10 클라이언트 열람 또는 동의 완료 시 리포트 재생성이 차단된다.
  • 재생성 시 버전 번호가 증가하며, 각 버전은 독립적으로 열람 가능하다.

클라이언트 확인 정책

6-1. 두 가지 확인의 구분
ℹ

6-2. 확인 링크 발급 및 유효 정책
  • 확인 링크는 UUID v4 토큰(122비트 엔트로피) 기반으로 발급된다. 클라이언트는 별도 가입 없이 접근 가능하다.
  • 토큰 유효 기간: 발급일로부터 30일. 만료 후 "이 확인 링크는 만료되었습니다." 안내 표시.
  • 만료 후 재발급 가능하며, 재발급 시 이전 토큰은 즉시 무효화된다.
  • 링크 전달 채널은 PM이 자유롭게 선택한다 (카카오톡, 이메일 등). 시스템이 클라이언트에게 자동 발송하지 않는다.
  • 확인 페이지는 robots.txt에 disallow 처리되어 검색 엔진에 노출되지 않는다.
6-3. 확인 기록의 불변성
!
핵심 원칙: scope_confirmed_at 또는 confirmed_at이 기록된 행은 어떠한 경우에도 삭제할 수 없다. 이는 분쟁 대비 증거 보존을 위한 시스템 수준의 강제 규칙이다.
  • 동의 완료 후에도 PM은 계약 범위를 수정할 수 있다. 단, 범위 수정 시 "범위 수정됨 — 클라이언트 재확인 권장" 경고 배지가 표시된다.
  • 동의 완료된 리포트(F-10)는 확인 링크 재생성이 불가하다.
  • 기록되는 정보: 동의 완료 시각(KST), 클라이언트 IP, 클라이언트 User-Agent. 이 정보는 내부 DB에만 저장되며 외부로 전송되지 않는다.
6-4. 확인의 법적 성격
  • 클라이언트 확인(동의 버튼 클릭)은 법적 구속력 있는 전자서명이 아닌, 내용 인지 확인 수준이다.
  • 확인 페이지에는 다음 고정 문구가 반드시 표시된다: "위 항목은 범위 확인을 목적으로 하며, 본 동의는 기존 계약을 대체하지 않습니다."
  • 동의 페이지에는 거절, 협상, 수정 요청 버튼을 제공하지 않는다. 확인 버튼 1개만 존재한다.
  • 내부 도구 원칙: Scope Manager는 PM의 내부 관리 도구이며, 클라이언트와 직접 협상하거나 압박하는 기능을 제공하지 않는다.
6-5. 클라이언트 확인 상태 표시

PM 화면에서 확인 상태는 3단계로 표시된다: 미열람 → 열람 완료 → 동의 완료

  • 최초 접근 시 열람 완료 시각이 별도 기록된다 (동의와 독립적 추적).
  • 동의 완료 시 PM에게 인앱 알림이 표시된다. 이메일 알림은 P2 단계에서 지원.
07

데이터 보관 및 보안 정책

7-1. 멀티테넌트 격리 원칙
  • 모든 DB 테이블에 organization_id UUID NOT NULL이 필수 적용된다.
  • Supabase RLS(Row Level Security)가 모든 테이블에 ENABLE FORCE 상태로 적용된다.
  • API Route 레벨에서도 WHERE organization_id = ? 조건을 명시하여 이중 격리를 보장한다.
  • 클라이언트 확인 페이지(/confirm-scope/[token], /confirm/[token])는 RLS 예외 처리되며, 토큰 자체가 인증 수단으로 작동한다.
  • 타 Organization 데이터 접근 시도 시 403 반환을 인수 기준으로 QA 검증한다.

7-3. 민감 데이터 처리 원칙
  • Claude API 키, Toss Payments 시크릿 키, Supabase Service Role 키는 서버사이드 전용으로만 사용된다. 클라이언트 코드에 절대 노출되지 않는다.
  • 클라이언트 IP 및 User-Agent는 내부 DB에만 저장되며, PostHog 등 외부 서비스로 전송되지 않는다.
  • PostHog 이벤트에는 개인정보 및 계약 세부 데이터가 포함되지 않는다.
  • Claude API 프롬프트 구성 시 해당 Organization 데이터만 컨텍스트로 주입된다. 타 Organization 데이터가 AI 응답에 영향을 미치지 않는다.

08

결제 및 환불 정책

8-1. 결제 수단 및 주기
  • 결제 수단: Toss Payments 정기결제 (카드 자동결제).
  • 결제 주기: 월간 구독, 매월 가입일 기준 자동 갱신.
  • 결제 플로우: 업그레이드 모달 → Toss Payments 위젯 → 결제 승인 Webhook → plan_type 업데이트 및 사용량 리셋.
  • Toss Payments 연동은 사업자등록 완료 후 활성화된다. 그 이전에는 유료 플랜 가입이 비활성화 상태로 유지된다.
8-2. 구독 해지 및 플랜 전환
  • 구독 해지 요청 시 당월 말까지 유료 기능을 유지한 후, 다음 달 1일부터 Free 플랜으로 전환된다.
  • 플랜 업그레이드 시 즉시 적용되며 사용량 카운터가 리셋된다.
  • 플랜 다운그레이드 시 다음 결제일부터 적용되며, 남은 기간은 상위 플랜 기준으로 유지된다.
8-3. 환불 정책
⚠
SaaS 서비스 특성상 결제 완료된 구독 기간에 대한 부분 환불은 원칙적으로 제공하지 않는다. 단, 서비스 장애 등 운영자 귀책 사유가 명확한 경우 개별 협의를 통해 처리할 수 있다.
  • 결제 당월 미사용 상태에서 7일 이내 환불 요청 시 전액 환불 처리한다 (운영 초기 정책, 향후 변경 가능).
  • 환불 요청 채널: 서비스 내 문의 기능 또는 운영자 직접 연락.
09

면책 및 법적 한계

9-1. 서비스 제공 범위의 한계
  • Scope Manager는 PM의 내부 의사결정 보조 도구이며, 법률 서비스를 제공하지 않는다.
  • 계약서의 법적 유효성, 완결성, 해석은 시스템이 검증하지 않는다. PM이 입력한 텍스트를 판정 기준으로 사용할 뿐이다.
  • AI 판정 결과, 생성된 리포트, 클라이언트 확인 기록이 법적 분쟁에서의 효력을 보장하지 않는다.
  • 시스템이 생성한 리포트를 클라이언트에게 전달할지, 어떤 채널로 전달할지, Scope Manager 사용 여부를 공개할지 모두 PM의 재량이다.
9-2. 내부 도구 원칙 (영구 제외 기능)

아래 기능은 한국 비즈니스 문화에서의 관계 리스크 및 법적 책임 문제로 영구 제외된다.

제외 기능제외 근거
클라이언트 포털 / 협상 제안서도구가 직접 압박 → 한국 비즈니스 관계 파괴 리스크. 내부 도구 원칙 위반.
AI 계약서 자동 생성법무 영역. AI 생성 계약서 법적 책임 리스크.
자동 청구서 발송 / 결제 연동청구는 PM의 최종 판단과 관계 맥락이 필요. 자동화 시 관계 손상 리스크.
자동 클라이언트 알림 발송카카오톡이 주 채널인 한국 비즈니스 환경에서 이메일 자동 발송은 채널 불일치. 도구 노출 리스크.
9-3. 서비스 안정성 면책
  • Supabase, Vercel, Claude API, Toss Payments 등 제3자 서비스 장애로 인한 Scope Manager 서비스 중단에 대해 운영자의 책임이 제한된다.
  • Claude API 오판정으로 인한 비즈니스 손해에 대해 Scope Manager는 책임을 지지 않는다.
10

정책 변경 원칙

  • 이 정책서는 PRD 버전 업데이트 또는 주요 기능 변경 시 함께 개정된다.
  • 플랜 가격, 사용량 한도, 환불 정책 변경 시 기존 유료 사용자에게 변경 30일 전 사전 고지한다 (인앱 알림 또는 이메일).
  • 데이터 삭제 정책, 증거 보존 원칙 (scope_confirmed_at, confirmed_at 불변성)은 서비스 존속 기간 동안 변경하지 않는 것을 원칙으로 한다.
  • 영구 제외 기능 목록은 제품 철학의 핵심이며, 비즈니스 전략적 판단에 의해서만 변경 가능하다.

이 문서는 Scope Manager PRD v2.1을 기반으로 작성된 내부 서비스 정책서입니다. 외부 공개 시 이용약관 및 개인정보처리방침 문서로 별도 변환이 필요합니다.
