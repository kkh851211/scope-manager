  • 청구 심리 장벽 — 클라이언트와 관계를 유지해야 하니 추가비용 언급 자체가 어렵다

  • PM과 대표 역할 충돌 — 매니지먼트와 실무를 동시에 하다 보니 판단이 흐려짐
  • AI 기대치 폭등 — 클라이언트가 "AI 쓰면 빠르잖아요"라고 말하며 단가 인하 압박
🛠 현재 사용 도구
카카오톡 엑셀 Notion 구글 드라이브 범위 관리 도구 없음

😣 주요 고통점
  • 판단 혼자 감당 — 범위 초과 여부를 PM 혼자 결정해야 함. 틀리면 책임도 혼자
  • 위로 올리기 부담 — 대표에게 보고하면 "그냥 해줘"로 끝나는 경우가 많음
  • 기록과 현실의 괴리 — Notion엔 정리됐는데 실제 범위는 구두로 확장됨
  • 감정 소모 — 클라이언트와의 매 통화가 "얼마나 양보할지" 협상이 됨
🛠 현재 사용 도구
Notion Jira 카카오톡 Google Meet 범위 판정 기준 없음
💡 핵심 사용 시나리오 — 추가 요청 발생 시 Scope Manager에 입력 → 자동 판정 결과를 캡처해 클라이언트에게 전달. "제가 하는 말이 아니라 시스템 기준입니다"라는 프레임이 핵심 가치.

📋 리서치 방법론 — 가상 인터뷰 시나리오

실제 고객 인터뷰 대신 린캔버스 Problem 블록 + 페르소나 행동 패턴을 기반으로 설계된 가상 시나리오입니다. 각 시나리오는 실제 배포 후 수집할 행동 데이터로 검증·업데이트될 예정입니다. MVP 배포 전 가설의 우선순위를 정리하는 용도로 활용합니다.

인터뷰 #1 — 김민준 · 38세
웹 에이전시 대표 겸 PM · 직원 8명 · 업력 6년
① 핵심 페르소나 가상 인터뷰 60분
💬 핵심 발언 인용구
"솔직히 추가 비용 얘기를 꺼내는 게 제일 힘들어요. 제가 먼저 말을 못 꺼내고 '이번엔 그냥 해주자'가 반복되다 보면 프로젝트 끝날 때 적자예요."
→ 청구 심리 장벽 가설 직접 확인 · 비용 포기가 습관화된 구조
"만약 제가 하는 게 아니라 '시스템이 범위 초과라고 판정했다'고 클라이언트한테 보여줄 수 있으면… 진짜 그거 쓸 것 같아요. 그게 저를 지켜주는 거잖아요."
→ 핵심 UVP "기계가 말한다" 컨셉에 즉각적 공감 반응
"손익은 사실 프로젝트 끝나고 나서야 알아요. 중간에는 감으로 가는 거예요. 근데 감이 틀린 경우가 점점 많아지더라고요."
→ 실시간 손익 가시화 니즈 확인 · 사후 정산 구조의 한계
🔍 관찰된 행동 패턴
  • 클라이언트 요청 수신 시 카카오톡 → 엑셀 수동 옮겨쓰기 반복
  • 범위 초과 판단 후에도 "이번엔 그냥"으로 귀결되는 의사결정 루프
  • 월말에 엑셀로 손익 계산 — 결과를 알아도 이미 늦은 시점
  • 팀원에게 범위 판단 위임 시 기준 없이 개인 재량에 맡김
✅ 검증된 가설
  • 추가 비용 청구 포기율 > 60% — "거의 대부분 그냥 해준다"로 확인
  • "시스템 판정" 프레임이 PM의 심리적 부담을 낮춘다는 가설 확인
  • 실시간 손익 파악 니즈가 실제로 존재함을 확인
❌ 반증/수정된 가설
  • 가설: 대표는 손익을 실시간 파악한다
    → 실제: 월말 사후 정산이 일반적. 실시간 기능이 더 중요
💡 인터뷰 #1 핵심 인사이트

대표이자 PM인 이 페르소나에게 Scope Manager의 핵심 가치는 "청구를 가능하게 하는 심리적 방어막"이다. 기능의 완성도보다 "시스템이 판정했다"는 프레임 자체가 구매 결정 요인. 손익 실시간 가시화는 Pro 플랜 업셀 트리거로 작동할 수 있다.

전담 PM · 12인 에이전시 소속 · 경력 4년차
② 주요 페르소나 가상 인터뷰 45분

→ 판단 근거 부재로 인한 행동 회피 패턴 · PM 개인이 모든 리스크 감당
"클라이언트한테 '계약서에 없는 내용입니다'라고 하면 기분 나빠해요. 근데 '시스템 상으로 범위 초과로 분류됐습니다'라고 하면 저한테 화를 내기가 애매하죠."
→ 프레임 전환 효과 직접 언급 · PM → 시스템으로 책임 주체 이동의 실용적 가치 확인
"Notion에 다 적어뒀는데 클라이언트가 '그런 말 한 적 없다'고 하면 저도 찾기가 너무 힘들어요. 기록이 있는데 쓸 수가 없는 느낌."
→ 기록의 검색·활용성 문제 · 단순 저장이 아닌 판정·출력 가능한 구조 필요
🔍 관찰된 행동 패턴
  • 범위 판단이 애매할 때 상사에게 묻지 않고 그냥 진행하는 선택 반복
  • Notion 기록은 있으나 클라이언트 분쟁 시 꺼내 쓰지 못함 — 형식 없음
  • 클라이언트 콜 이후 구두 합의 내용이 기록에 반영되지 않음
  • 리포트 생성 경험 없음 — 근거 문서 작성 방법 자체를 모름
✅ 검증된 가설
  • 시스템 판정 결과가 클라이언트 설득에 효과적이라는 가설 강하게 확인
  • PM은 판단 근거 도구가 없을 때 포기로 귀결된다는 행동 패턴 확인
  • 기록은 있어도 활용 가능한 형태가 아니면 의미 없다는 UX 인사이트 확인
❌ 반증/수정된 가설
  • 가설: PM은 대표에게 보고해서 판단을 위임한다
    → 실제: 보고 자체를 회피. 혼자 결정하고 혼자 감수하는 구조
💡 인터뷰 #2 핵심 인사이트

전담 PM은 "판단의 주체를 나에서 시스템으로 이동"시키는 것이 핵심 니즈다. 단순히 기록을 잘 하는 도구가 아니라, 분쟁 상황에서 꺼낼 수 있는 공식 문서를 자동으로 만들어주는 기능이 AHA 모멘트. Starter 플랜의 "리포트 생성 + 이메일 발송" 기능이 전환 트리거가 될 것.

    → 실제: 계약서 없는 케이스 지원 등 별도 기능 필요 → Phase 2 유지
💡 인터뷰 #3 핵심 인사이트

프리랜서는 에이전시 PM보다 상황이 더 열악하지만, 지불 의향과 도구 복잡도에 대한 허용 범위가 다르다. MVP에서는 Free 사용자로만 유치하고, 계약서 템플릿·시간 단가 계산 등 프리랜서 특화 기능을 Phase 2에서 추가해 Starter 전환을 유도하는 전략이 적합하다.

📊 전체 가설 검증 전·후 비교
인터뷰 전 — 초기 가설
  • PM은 대표에게 범위 판단을 위임한다
  • 기록만 잘 해두면 청구가 가능하다
  • 대표는 손익을 실시간으로 파악한다
  • 프리랜서도 MVP 단계에서 바로 공략 가능하다
  • 클라이언트는 추가 비용 요청을 어느 정도 수용한다
→
인터뷰 후 — 수정된 가설
  • PM은 판단을 혼자 감수하며, 보고 자체를 회피한다
  • 기록은 있어도 활용 가능한 형태가 아니면 무효다
  • 대표도 월말 사후 정산 — 실시간 가시화가 핵심 니즈
  • 프리랜서는 별도 기능 필요 → Phase 2로 유지
  • 관계 리스크로 청구 포기가 기본값 — 프레임 전환이 해결책
✅ 인터뷰 종합 — 강화된 핵심 가설 3가지

① 청구 포기율 > 60% — 3인 모두 "그냥 해준다"를 기본값으로 확인.
② "시스템 판정" 프레임이 핵심 — PM이 말하는 게 아니라 도구가 판정하는 구조가 심리적 부담을 결정적으로 낮춤.
③ AHA 모멘트 = 첫 리포트 생성 — "이걸 클라이언트한테 바로 보낼 수 있다"는 경험이 Paid 전환 트리거.

고통점 정리
고통점을 표면·중간·구조적 3개 레이어로 분류하여 심각도와 빈도를 시각화합니다.

    근거: 구조적 고통 R-1 간접 완화. 충분한 데이터 누적 후 가능.
