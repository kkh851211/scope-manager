문서 개요
이 문서의 목적, 버전별 정의, 기능 분류 기준, 관련 문서와의 연결 구조를 정의합니다.
📌 이 문서의 목적과 사용 방법

기능 목록표(Feature List)는 Scope Manager의 전체 기능을 버전별로 분류하고, 각 기능이 어느 시점에 만들어지는지를 명확히 정의하는 문서다.

누가 사용하는가 — Antigravity(AI IDE)로 빌드할 때 "이 기능이 지금 버전에 포함되는가?"를 판단하는 기준 문서로 활용한다. 기능 범위 결정이 모호할 때, 버전 간 우선순위를 조정할 때, 외부에 로드맵을 설명할 때 이 문서로 돌아온다.

다른 문서와의 차이 — PRD는 기능의 요구사항(What·How)을 정의하고, 유저 스토리는 기능의 맥락(Who·Why)을 정의한다. 이 문서는 기능의 시점(When)을 정의한다.

버전 결정 제1원칙
"PMF 검증 전에는 최소한으로 만들고 빠르게 배포한다.
데이터가 쌓이기 전까지 기능 추가는 가설일 뿐이다."
기능을 더 넣을수록 배포가 늦어지고, 배포가 늦어질수록 실제 사용자 행동 데이터를 얻지 못한다.
지금 당장 만들지 않아도 되는 기능을 식별하는 것이 이 문서의 핵심 가치다.

🚀 MVP 기능 목록 — F-01 ~ F-05
F-01
이메일 / 소셜 로그인 & 인증
P0 Claude API 없음 🚀 MVP v1.0
이메일+비밀번호 또는 Google OAuth 2.0으로 가입·로그인한다. Supabase Auth가 JWT 세션 토큰을 발급하고, 모든 이후 API 요청에 인증이 적용된다.
📌 포함 근거
인증 없이는 어떤 기능도 안전하게 제공 불가. 테넌트 격리(F-02)의 선행 조건.
👥 연결 유저 스토리
US-O-01 — Google 1클릭으로 빠르게 로그인
US-P-01 — 이메일로 워크스페이스 로그인
🛠 기술 구현
Supabase Auth · Google OAuth 2.0 · JWT · Next.js Middleware 라우트 보호
✅ 완료 기준 (Definition of Done)
  • Google OAuth 로그인 후 대시보드 진입 확인
  • 이메일+비밀번호 가입 → 인증 메일 수신 → 링크 클릭 → 로그인 성공
  • 비로그인 상태에서 /dashboard 접근 시 /login으로 리다이렉트
  • 로그아웃 후 세션 토큰 무효화 확인
  • PostHog user_signed_up 이벤트 수신 확인
F-02
워크스페이스 격리 & Row Level Security
P0 Claude API 없음 🚀 MVP v1.0
가입 시 에이전시 단위 워크스페이스(organization)를 자동 생성한다. Supabase RLS(Row Level Security)로 모든 테이블에 organization_id 기반 격리를 적용해 타 에이전시 데이터 접근을 원천 차단한다.
📌 포함 근거
B2B SaaS의 최소 신뢰 기반. 데이터 격리 없이 어느 에이전시도 실데이터를 입력하지 않는다. 테넌트 격리 없는 AI 판정은 프롬프트 오염 위험.
👥 연결 유저 스토리
US-O-02 — 워크스페이스 격리 확인
US-P-01 — 우리 팀 데이터만 접근
🛠 기술 구현
Supabase RLS 정책 · organizations 테이블 · organization_members 연결 · API Route 레이어 검증
✅ 완료 기준 (Definition of Done)
  • 에이전시 A 계정으로 에이전시 B의 프로젝트 조회 시 빈 목록 또는 403 반환
  • 가입 시 organizations + organization_members 레코드 자동 생성 확인
  • RLS 정책 — projects, scope_definitions, scope_requests, reports 전체 테이블 적용 확인
  • Supabase Studio에서 RLS 활성화 상태 확인
  • Claude API 프롬프트 컨텍스트에 타 에이전시 데이터 미포함 확인
F-03
프로젝트 생성 & 계약 범위 등록 (AI 파싱)
P0 Claude API 1회 🚀 MVP v1.0
프로젝트를 생성하고 계약서 텍스트를 붙여넣으면 Claude API가 1회 호출되어 범위 항목을 구조화된 JSON 배열로 파싱한다. PM이 결과를 검토·수정 후 확정하면 scope_definitions에 저장되고, 이후 모든 판정의 기준이 된다.
📌 포함 근거
판정의 기준 데이터가 없으면 F-04(판정), F-05(리포트) 모두 작동 불가. 핵심 루프의 첫 번째 입력 단계.

F-04
클라이언트 요청 입력 & AI 범위 판정 (Fast Path 포함)
P0 Claude API 조건부 🚀 MVP v1.0
클라이언트 추가 요청을 입력하면 Fast Path(키워드 매칭·캐시)를 먼저 체크한다. 미적중 시에만 Claude API를 호출해 범위 내/판단 필요/범위 초과 3단계로 판정하고, 계약서 항목 번호와 연결된 근거 문장을 함께 출력한다. PM이 결과에 이의 있으면 수동 오버라이드가 가능하다.
📌 포함 근거
제품의 핵심 가치 자체. "기계가 판정한다"는 경험이 없으면 PM이 직접 말해야 하고, 그러면 이 제품은 필요 없다.

F-05
리포트 자동 생성 & PDF 다운로드
P0 Claude API 1회
⭐ AHA 모멘트 🚀 MVP v1.0
범위 초과 판정 결과를 바탕으로 Claude API가 한국어 중립 어조의 리포트 초안을 자동 생성한다. PM이 검토·수정 후 확정하면 PDF로 다운로드할 수 있다. "내가 쓴 글이 아니라 시스템이 만든 공식 문서" — 이 경험이 Free → Paid 전환의 핵심 트리거다.
📌 포함 근거
제품의 AHA 모멘트. 판정만 있고 리포트가 없으면 PM은 여전히 직접 말해야 한다. 이 기능이 "기계가 대신 말한다"는 가치를 완성한다.

데이터 내보내기 (CSV / Excel)
P2 Claude API 없음 🟣 v2.0
프로젝트별 판정 이력·손익 데이터를 CSV 또는 Excel 파일로 내보낸다. 에이전시 대표가 자체 스프레드시트나 회계 도구에서 추가 분석·보고할 때 활용한다.
📌 이 버전에 넣는 이유
데이터가 쌓이면 "외부로 꺼내고 싶다"는 니즈가 생긴다. 자체 분석·회계 연동 수요는 Pro 플랜 유저에게 집중.
👥 연결 유저 스토리
US-O-06 — 과거 데이터 기반 단가 조정
회계·경영 보고 목적 데이터 활용
🛠 기술 구현
SheetJS / papaparse · 커스텀 컬럼 선택 UI · 날짜 범위 필터
📡 선행 PMF 신호
  • Starter 사용자 인터뷰에서 "데이터 뽑아서 엑셀로 보고 싶다" 요청 3건 이상
  • 손익 뷰(F-07) 활성 사용자 중 외부 도구 병행 사용 패턴 확인
F-15
판정 커스텀 규칙 & 템플릿 라이브러리
P2 Claude API 선택적 🟣 v2.0
자주 반복되는 요청 유형에 대해 PM이 직접 판정 규칙을 정의하거나, 업종별 표준 계약 범위 템플릿을 라이브러리에서 불러온다. 계약서 없이도 빠르게 범위를 정의할 수 있다.
📌 이 버전에 넣는 이유
Fast Path 캐시가 쌓이면 "자주 오는 요청 유형을 미리 규칙으로 만들고 싶다"는 파워유저 니즈가 생긴다. 계약서 없이 시작하는 신규 사용자 온보딩 마찰도 줄인다.
👥 연결 유저 스토리
전담 PM이 반복 요청 유형에 대해 사전 규칙을 설정하는 시나리오 (v2.0 신규)
🛠 기술 구현
custom_rules 테이블 · 규칙 빌더 UI · 템플릿 라이브러리 DB · Fast Path 규칙 엔진 연동
📡 선행 PMF 신호
  • Fast Path 경로 C(캐시 적중) 비율이 전체 판정의 40% 이상 — 반복 요청 패턴이 충분히 쌓인 상태
  • "계약서 없이도 바로 쓸 수 있으면 좋겠다"는 온보딩 이탈 피드백 반복
  • 파워유저(월 판정 10건 이상)가 오버라이드를 반복하는 패턴 — 커스텀 규칙 니즈 신호
🟠 v2.0+ 기능 — P3 (시장 확장·미래 검토)
⚠️ P3 기능 — 현재 사이클에서 만들지 않는다

아래 기능들은 별도의 PMF 재검증이 필요하거나, 현재 타겟(한국 5~20인 웹 에이전시) 외 세그먼트로 확장할 때 검토한다. 로드맵에 기록해두되, 위의 신호가 나오기 전까지 개발 리소스를 투입하지 않는다.
