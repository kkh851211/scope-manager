문서 개요
화면 기능 명세서(Screen Spec)의 목적, 읽는 법, 표기 규칙, 관련 문서와의 관계를 정의합니다.
📌 이 문서의 목적과 사용 방법

Screen Spec은 Scope Manager의 각 화면을 실제로 구현할 때 필요한 모든 정보를 담은 문서다. UI 요소 목록·동작 명세·유효성 검사·예외 처리·API Route 연동·Claude API 호출 조건까지 개발자(혹은 AI IDE)가 화면 한 장을 처음부터 끝까지 구현하는 데 필요한 내용을 한 곳에 정리한다.

누가 사용하는가 — Antigravity(AI IDE)로 Next.js 페이지·컴포넌트를 생성할 때, 각 화면의 props·상태·API 호출 패턴을 확인할 때, QA 시나리오를 작성할 때 이 문서를 기준으로 삼는다.

다른 문서와의 차이 — IA는 화면 구조와 URL, PRD는 기능 요구사항을 정의한다. Screen Spec은 화면 안에서 일어나는 모든 동작과 예외를 정의한다.

Screen Spec 작성 원칙
"UI 요소 → 정상 동작 → 예외 처리 순서로 읽는다.
Claude API 호출이 있는 화면은 Fast Path 분기를 먼저 확인한다."
명세는 구현 가능한 수준으로 구체적이어야 한다. "버튼을 클릭한다"가 아닌 "클릭 시 /api/judge POST 호출 → 로딩 상태 전환 → 응답 수신 후 결과 렌더링"까지 서술한다.

② 미들웨어 처리 흐름
시스템
모든 요청 인터셉트 → Supabase createServerClient()로 세션 쿠키 확인 → 세션 갱신(refresh) 수행 → 라우트 보호 규칙 적용. Supabase SSR 패키지(@supabase/ssr) 사용.
시스템
redirect 파라미터 처리 — 로그인 후 원래 페이지로 복귀. /login?redirect=/dashboard/projects/[id]/request 형태. 로그인 성공 시 searchParams.get('redirect') 읽어 해당 경로로 이동.
시스템
matcher 설정 — 정적 파일(_next/static, _next/image, favicon.ico)은 미들웨어 제외. API Routes(/api/*)는 별도 인증 미들웨어 없음 — 각 Route Handler에서 Supabase 세션 직접 확인.
🔒 API Route 인증 처리

모든 /api/* Route Handler는 미들웨어가 아닌 핸들러 내부에서 인증 확인. const { data: { session } } = await supabase.auth.getSession(). 세션 없으면 return Response.json({ error: 'Unauthorized' }, { status: 401 }).
